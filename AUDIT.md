## Canonical policy and metric contract

The integration contract is REBUILD_CONTRACT.md (local receipt: `docs/REBUILD_CONTRACT.md`). Policy `canonical-v2` retains conservative behavior: deduplicate exact and representation-equivalent copies; merge complementary cost only with matching other fields; quarantine contradictory event variants. Assume M/D for ambiguous slash dates, accept explicit unambiguous D/M exceptions and flag ambiguity. Preserve 2026 dates outside the analysis period. Keep null and invalid negative cost unknown, and keep valid observed cost 10. Orphans remain in total event counts but cannot enter an output-based rate numerator.

For a scope of `m` full months, reference intensity equals `1,000 × eligible linked defect events / (m × sum(master monthly_output for every product in the selected cohort))`. Products with zero events stay in the denominator. Severity, location, defect type and inspection-method filters restrict events only. No actual output history or unit identifier exists, so the value is an assumption-based event intensity. It is not yield or a measured percentage of defective products. Repair cost uses local currency. Unknown costs never become zero; observed cost coverage is disclosed.

Scenario calculations remain separate from canonical. Excluding cost 10 changes financial availability only; ambiguous D/M and hypothetical restoration of 2026 to 2024 are declared assumptions. Canonical report generation does not change the current user scope. The engine owns all calculations, and immutable contexts identify dataset, policy, filters and scenario.
